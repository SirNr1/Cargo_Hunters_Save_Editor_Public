# Cargo Hunters Save Editor 🛠️

[English](README.md) · **Русский**

Редактор сохранений для игры **Cargo Hunters** (`offline.save`, Steam App ID `4197990`).
Написан на Python и Tkinter, распространяется как портативное приложение для Windows.

Названия предметов, навыков, торговцев и отправителей писем читаются из файлов самой игры,
поэтому вы работаете с понятными названиями, а не с идентификаторами GUID.

## ✨ Возможности

* **🎒 Инвентарь и снаряжение**
  * Редактирование предметов в снаряжении персонажа, в убежище и на вкладках склада.
  * Дублирование с учётом стаков и указанием количества копий.
  * Починка предмета вместе со всем, что к нему присоединено.
  * **Задать состояние...** ставит выбранное значение вместо максимума, и каждый предмет
    держится **своего** предела: 250 подходит щиту и бессмысленно для ремкомплекта на пять
    зарядов, так что одно значение на всю винтовку не перехлёстывает на мелких деталях.
  * **Как новое** — галочка в том же окне и кнопка на всё сохранение сразу. Она делает
    обратное установке значения: **убирает** запись об износе — состояние, отметку о том, с
    чем предмет пришёл, и заряды. Именно это игра считает новым состоянием, а починка до
    максимума им не является: у новой DORA игра не хранит состояния вовсе, тогда как
    починенная винтовка стоит на максимуме и всё равно читается как починенная. Предмет,
    который уже новый, так и скажет, вместо того чтобы молча ничего не сделать.
  * **Задать размер стака...** записывает, сколько единиц в стаке, вплоть до вместимости
    самого предмета. Свободная клетка не нужна, в отличие от дублирования, а значение вне
    диапазона отклоняется, а не обрезается молча. То, что игра никогда не стакала, стаком не
    становится.
  * **Групповая строка раскрывается.** `12x70 AP (10 стаков, 200 единиц)` — это десять
    отдельных предметов, и теперь каждый из них стоит своей строкой ниже: действие касается
    именно этого стака, а не требует выбрать номер из списка, которого не видно.
  * **Переместить предмет...** переносит предмет в другой контейнер. Навески перемещаются
    вместе с ним, а надетый предмет освобождает свой слот.
  * **Разделить стак...** отделяет часть стака во второй, по умолчанию половину. Хотя бы одна
    штука остаётся на месте: отделить всё — это перемещение, а не разделение.
  * **Навески...** ставит детали на предмет и снимает их обратно. В одном окне показаны слоты
    самого предмета с тем, что в них стоит, а для детали — ваши предметы, на которые она
    подходит: прицел переезжает с одной винтовки на другую напрямую. Свободный слот предлагает
    ровно те детали, которые игра туда пускает, из ваших собственных. Слоты есть у оружия, у
    его частей, у частей тела и у шлемов.
  * **Поиск** фильтрует дерево по названию, категории или идентификатору. Найденное внутри
    контейнера раскрывает этот контейнер, так что прицел на винтовке в оружейном кейсе видно
    там, где он лежит. Пустое поле снова показывает всё.
  * Удаление предмета вместе со всем присоединённым — или, если раскрыть предмет, удаление
    одной насадки: прицел снимается, а винтовка остаётся на месте.
* **🔍 Информация о предмете**
  * Правый клик → **Информация о предмете**, и в инвентаре, и в каталоге. Только для чтения.
  * Цена в кредитах, вес, размер в сетке (с максимумом для оружия, которое растёт),
    вместимость стака и то, какое состояние предмет вообще может нести. Из инвентаря видно
    ещё и состояние конкретного экземпляра, его количество и где он лежит.
  * **Что даёт переработка.** Результат зависит от того, насколько построен ваш переработчик,
    поэтому показаны все уровни, а доступный вам отмечен:

    ```
    Переработка                        ваш переработчик: уровень 1
      ▸ Уровень 1    2.5 ч    10x Кислота
        Уровень 2    2 ч      500x Свинец, 5x Кислота
    ```

    Уровень переработчика читается из вашего сохранения. Если всем рецептам нужен модуль
    выше вашего, редактор так и скажет, а не отметит строку, которой вы не сможете
    воспользоваться. Перерабатываются 426 из 1595 предметов; про остальные прямо сказано,
    что нельзя.
  * **Для чего предмет нужен** — рецепты, где он является ингредиентом, и сколько штук
    каждому нужно. Стоит посмотреть, прежде чем что-то разбирать.
  * **Какие патроны подходят оружию** и наоборот: у патрона перечислено оружие под него.
    36 стволов и 95 патронов на 14 калибров, и для каждого ствола патрон находится.
  * **Куда ставится деталь** — деревом: дульное устройство идёт на ствол, ствол в ствольную
    коробку, коробка в оружие. А если открыть саму деталь, названо **оружие**, на котором она
    в итоге окажется, а не промежуточная коробка. Не только оружие: у руки видно гидравлику и
    структуру, у забрала — шлем.
* **📍 Выбор места для нового предмета**
  * Дублирование и добавление из каталога сначала спрашивают, куда положить, и перечисляют
    все контейнеры, где есть место: `Вкладка 1 - свободно 73 из 240 клеток`.
  * Свободное место ищется внутри выбранного контейнера; предмет поворачивается на 90°
    только если иначе не помещается. Для десяти копий ищется десять мест, и если поместилась
    лишь часть — редактор скажет об этом, а не бросит остальное куда попало.
  * **Входящие** предлагаются всегда, даже когда всё занято: игра выдаст предмет письмом.
  * **Убежище** не предлагается: файлы игры не описывают его сетку, и редактор не угадывает
    размер.
  * **Оружию нужно место и нужны его детали.** Оружие занимает больше, чем нарисовано:
    пистолет размером 2x1 может держать четыре клетки. Поэтому редактор оставляет это место
    свободным вокруг оружия, которое уже лежит в контейнере, вместо того чтобы класть что-то
    туда, где игра считает занято. И оружию, созданному само по себе, он добавляет детали, без
    которых оно не существует, — затвор или ствольную коробку. Без того и другого игра просто
    возвращает оружие письмом.
* **📦 Полный каталог предметов**
  * Вся база предметов из файлов игры: категории, размеры в сетке, вместимость стака.
  * Добавление любого предмета из каталога прямо в инвентарь.
  * Стакающиеся предметы добавляются настоящими стаками; колонка **Stack** показывает,
    сколько единиц помещается в один.
  * У предметов, которые изнашиваются, есть ещё одно поле: состояние, с которым они
    появятся. При максимуме предмет создаётся идеальным — именно так игра хранит нетронутый
    предмет, вообще без поля состояния.
  * Колонки **Цена** и **Вес** прямо из данных игры. Цена есть у 1110 из 1595 предметов, вес
    у 1162; у остальных стоит прочерк, а не ноль: «цена не указана» и «стоит ноль» — разные
    утверждения.
  * **Создать оружие в сборе**, таким, каким его выпускает игра: правый клик →
    **Создать в сборе...** и выбрать конфигурацию. Их 53 на 35 стволов, от одной до семи
    деталей, и взяты они из списка пресетов самой игры — таблицы добычи, где что-то отдано на
    волю случая, не берутся вовсе, а не разыгрываются за вас. 17 конфигураций в сумме больше
    того, до чего оружию разрешено вырасти; редактор скажет об этом заранее, а не оставит игре
    отвечать письмом.
* **🤝 Подмена товара у торговца**
  * Временно поместить предмет из каталога в ассортимент торговца и купить его в игре.
  * Возвращается само при следующем обновлении ассортимента — или сразу, кнопкой **Undo**
    (действует только в текущем сеансе редактора).
* **📬 Почта**
  * Письма с отправителем, наградами и статусом прочтения. Удаление отдельных писем.
* **🗺️ Квесты (только для чтения)**
  * Все квесты игры против тех, что встретило ваше сохранение — **302 против 179** в реальном
    сохранении, и в этом весь смысл: сохранение знает только те квесты, с которыми вы уже
    столкнулись, поэтому остальные могут прийти лишь из файлов самой игры.
  * Сгруппированы так, как их группируют разработчики, а внутри — по признаку «активен»,
    «выполнен» или «ни разу не встречен». Ветки «ни разу не встречен» открыты сразу, чтобы
    ответ был виден при открытии вкладки. Выберите квест — и внизу появится полное описание,
    что нужно выполнить до него, кто его выдаёт и что за него платят.
  * Две оговорки: **67 из невстреченных — ежедневные** из сменного пула, а 21 помечен как
    устаревший, то есть вырезанное содержимое, которое появиться не может. И **прогресс не
    показывается**, потому что его нет в сохранении: игра хранит цель квеста, но не то,
    насколько вы к ней продвинулись.
  * **Поиск** идёт по названию, тексту задания, отправителю, группе и идентификатору —
    хватит и полузабытой строки из письма, чтобы найти квест, из которого она.
* **🔧 Крафт (только для чтения)**
  * Все рецепты верстаков в игре — 150 штук на семи модулях убежища — с тем, что нужно, что
    получится и сколько это займёт.
  * Ваш собственный склад считается против каждого рецепта, поэтому строка читается как
    **готово**, **не хватает ингредиентов**, **нужен уровень выше** или **ещё нет в игре**.
    Последнее не выдумка: некоторым рецептам нужен уровень верстака, для которого в игре нет
    ступени постройки.
  * 976 рецептов переработчика здесь не повторяются — они в **Информации о предмете**, по
    предмету, где вопрос звучит как «что я за это получу».
  * **Поиск** ищет по модулю, названию рецепта и результату — а ещё по расходуемым
    ингредиентам, так что ввод ингредиента отвечает на другой вопрос: не «как это сделать»,
    а «на что вообще годится этот хлам в рюкзаке».
* **☢️ Лаборатория Хакермана**
  * Никнейм, уровень, опыт, уровни навыков, уровни и балансы торговцев.
  * Все пределы берутся из данных самой игры, а не заданы в коде: у каждого навыка **свой**
    максимум (его и ставит кнопка `MAX`), уровень персонажа останавливается там же, где его
    останавливает игра, а баланс торговца — на той сумме, которую этому магазину разрешено
    держать. Всё, что больше, игра молча урежет при следующей загрузке.
  * Опыт ограничен целью текущего уровня, и сама цель показана рядом с полем. Сначала
    задайте уровень: при его смене опыт сбрасывается в 0.
  * **Свободные очки навыков** можно добавлять, и они намеренно не ограничены.
  * Вкладка **Статистика** показывает счётчики аккаунта — сессии, последний рейд и общие
    итоги. Только для просмотра.
  * Пять кнопок в один клик: **Макс. все навыки**, **Заполнить баланс торговцев**,
    **Починить все вещи**, **Заполнить все стаки** — каждый неполный стак до вместимости
    самой вещи — и **Всё как новое**, снимающее запись об износе со всего сохранения.
    Последние две сначала спрашивают, а потом сообщают, скольких вещей коснулись; как и любая
    другая правка, до применения ничего не записывается.
  * Может испортить сохранение — на самой вкладке об этом написано прямо.
* **🛡️ Изменения не пишутся сразу**
  * Всё накапливается в памяти. Файл сохранения не трогается, пока вы не нажмёте
    **Применить изменения**.
  * **Применить изменения сначала показывает список и ждёт подтверждения.** Каждый добавленный
    предмет, каждый удалённый, каждое изменённое поле — сгруппированы и названы. Сравнение идёт
    с файлом на диске, а не с тем, что редактор прочитал при запуске, поэтому в список попадёт
    и то, что игра успела изменить сама. Отмена — и ничего не записано. Тот же список
    показывается **перед возвратом резервной копии**, объясняя, что именно она отменит, и по
    запросу — как **сравнение сохранения с любой копией**.
  * Перед каждой записью создаётся резервная копия с отметкой времени в папке `backups/`
    рядом с программой.
  * Поле **Keep backups** справа внизу ограничивает их число: по умолчанию 20, значение 0
    хранит все. Удаляются только файлы, которые редактор назвал сам, — ваши собственные
    копии в этой папке в безопасности.
  * **Restore backup...** рядом возвращает копию на место, не выходя из редактора: выберите
  * **Reload Save** в правом верхнем углу читает файл заново, не закрывая редактор.     её из списка по времени, причине и размеру — редактор заменит сохранение и перечитает
    его. Текущее сохранение сначала откладывается как `before_restore`, так что отменить
    отмену — ещё один щелчок. Файл, который редактор не создавал сам, не предлагается вообще,
    а выбор, который окажется не сохранением, отклоняется **до** того, как ваш файл будет
    затронут, а не на половине пути.
* **🌍 Три языка**: английский, немецкий и русский.

Состояние предмета показывается рядом с названием: `COND` по игровой шкале 0–4 для снаряжения
и `DUR` как остаток зарядов для расходников — например, `DUR 3.0/5 (60%)` для ремкомплекта.
Максимумы берутся из данных игры для каждого шаблона, а не считаются от произвольного числа.
У предметов, которых игра ещё не касалась, этих полей нет вовсе — тогда не показывается ничего.

## 🚀 Как запустить

Скачайте архив из раздела [Releases](../../releases), распакуйте в любую папку с правом
записи и запустите `CargoHuntersEditor.exe`. Установка не нужна, Python не нужен.

Редактор сам ищет сохранение: текущая папка, все буквы дисков и путь Steam
`userdata/*/4197990/remote/offline.save`. Задать файл вручную можно ключом `--save-path`.

## ⚠️ Windows предупредит при первом запуске

Сборка не подписана сертификатом, поэтому два предупреждения — это нормально, и ни одно из
них не означает, что с файлом что-то не так:

* **SmartScreen** — «Система Windows защитила ваш компьютер».
  Нажмите **Подробнее → Выполнить в любом случае**.
* **Антивирус** — исполняемые файлы, собранные PyInstaller, дают ложные срабатывания
  постоянно: этим упаковщиком пользуются и обычные программы, и вредоносные.

Программа не выходит в сеть. Она записывает только ваше сохранение и резервные копии в папке
`backups/` рядом с собой.

Если не хотите доверять готовому файлу — запустите из исходного кода. Это тот же самый код.

## 🧑‍💻 Запуск из исходного кода

Нужен Python 3.11+ с `tkinter`.

```bash
python CH_Editor/gui_editor.py
python CH_Editor/gui_editor.py --save-path "путь/к/offline.save"
```

`UnityPy` нужен только для кнопки **Refresh Names from Game**, которая заново вычитывает
названия из ресурсов игры. Готовая таблица названий входит в сборку, так что без него
работает всё остальное.

```bash
pip install UnityPy   # только если хотите обновить названия сами
```
